# Aucton

Windows용 옥션 자동입찰 도구입니다. 정밀 모드는 가격을 미리 확정하는 **고정가 입찰에만** 적용됩니다. 100µs는 내부 스케줄러의 목표 해상도이며 Windows, Chrome, 네트워크를 포함한 서버 등록 정확도를 보장하지 않습니다.

## 최신 실행 파일과 로그인 방식

최신 수정본은 `dist/login-click-fix/main/main.exe`입니다. 같은 폴더의 `_internal`을 함께 유지합니다. 창 제목은 `옥션 · 자동/수동 로그인 · 로그인 클릭 수정본`입니다. 이전 EXE와 실행 중인 창은 덮어쓰거나 종료하지 않았습니다.

로그인 버튼을 누르는 중 비밀번호 입력 오류 문구가 사라져 버튼이 이동하고 클릭이 누락되는 문제를 실제 페이지에서 재현했습니다. 버튼으로 포커스를 먼저 옮기고 위치가 150ms 동안 안정된 뒤 정상 클릭을 한 번 수행합니다. 실제 선택 계정 시험에서 인증 POST와 메인 페이지 이동은 확인했지만, 메인 페이지의 봇 확인이 8초 내 완료되지 않아 로그인 성공은 확인하지 못했습니다. 이 환경에서는 **수동 로그인 (창 표시)**을 사용해야 합니다. 자동 모드는 보안 확인을 우회하거나 요청을 재전송하지 않습니다.

기존 고정 주소 `Authenticate/Default.aspx`가 오류 페이지로 이동하는 것을 확인해 `Authenticate/Login.aspx`로 수정했습니다. 현재 서비스가 이동시킨 `Authenticate/MobileLogin.aspx`에서 실제 빈 아이디·비밀번호 입력칸과 로그인 버튼이 표시되는 것까지 확인했습니다. 실계정 인증 성공이나 실입찰을 확인한 것은 아닙니다. 봇 확인 페이지는 일반 주소 오류와 구분해 안내하며 방화벽 설정은 자동 변경하지 않습니다.

- **자동 로그인 (창 표시)**: 계정 목록에서 사용할 계정을 선택하고 자동 로그인을 체크한 뒤 시작합니다. Windows Credential Manager에 저장한 해당 계정의 비밀번호를 사용합니다. 비밀번호가 없다면 계정 등록에서 저장합니다. 자동 로그인도 Chrome 창을 표시합니다.
- **수동 로그인 (창 표시)**: 브라우저를 띄우고 직접 로그인합니다. 자동 감지 또는 로그인 완료 버튼으로 확인한 뒤 입찰을 준비합니다. 기본 선택은 수동 로그인입니다.

두 선택은 상호 배타적이며, 작업 중에는 로그인 방식과 계정 선택을 바꿀 수 없습니다. 추가 인증·보안문자나 인증 오류가 나오면 자동 로그인은 중단하고 수동 로그인 선택을 안내합니다. 자동 로그인은 폼 제출을 한 번만 시도합니다. 비밀번호를 작업 명세·설정 JSON·로그에 넣지 않습니다.

진행 상황에는 상품명·현재가·입찰자 수, 모드·계정(마스킹)·예약 시각, 계산 입찰가와 한도, 가격 입력·장전·대기, 클릭 시각·서버 등록 확인·결과·미제출 사유를 출력합니다. 최근 1,000줄을 유지하며 시각과 작업 ID로 구분합니다. 미확인 결과를 성공이나 낙찰로 표시하지 않습니다.

## 앱 전용 브라우저

시스템 Chrome을 사용하지 않습니다. 릴리스에는 공식 Chrome for Testing `157.0.8103.38`과 같은 버전의 ChromeDriver를 아래 위치에 함께 넣습니다.

- `browser/chrome-win64/chrome.exe`
- `browser/chromedriver-win64/chromedriver.exe`

`browser_manifest.json`과 두 실행파일의 실제 버전이 완전히 같아야 합니다. 릴리스에서는 SHA-256 값도 채웁니다. 검증 실패 시 입찰은 차단되며 전체 패키지를 다시 설치해야 합니다. 브라우저 갱신은 별도 릴리스에서 로그인, 팝업, dry-run을 검증한 뒤 manifest와 바이너리를 함께 교체합니다.

## 시간 보정과 정밀 모드

실행 시각은 `목표 서버 시각 - 서버·PC 시계 차이 - 자동 보정 - 수동 보정`입니다. 서버 시계 차이를 검증하지 못한 기본 상태에서는 0ms를 가정한다고 알리고 자동 학습을 보류합니다. 수동값은 -500~+500ms이며 양수는 앞당기고 음수는 늦춥니다. 일반 모드는 자동·수동 지연 보정을 적용하지 않습니다.

고정가는 가격 사전입력 후 Python 단조 시계와 브라우저 `performance.now()`를 대응시키고 브라우저상의 절대 목표를 장전합니다. 장전 승인은 즉시 반환합니다. 모든 작업의 준비·장전 승인이 최초 실행시각 300ms 전까지 완료되어야 합니다. 마지막 2ms만 spin하며 5ms 넘게 지각하면 제출하지 않고 만료합니다. 장전 후 응답 유실·타임아웃은 결과 불명으로 처리하며 재클릭이나 Python fallback은 수행하지 않습니다. 일반 입찰은 목표 도달 후 새로고침과 최신 가격·한도 검사 후 제출합니다.

상품 정보는 현재 로그인한 브라우저 DOM에서 읽습니다. 별도 HTTP 세션의 응답 때문에 로그인 직후 중단되던 경로를 제거했습니다. 상품 화면 자체가 차단되거나 경매 요소가 없으면 구체적인 오류로 중단합니다.

`latency_history.json`은 보존하고 새 `latency_history_v2.json`만 사용합니다. 모드별 유효 20건 중 최근 5건의 중앙값을 사용합니다. 이번 시도의 비마스킹 계정·가격·등록시각을 제출 전후 기록에 유일하게 연결하고 시계 불확실성이 1ms 이내일 때만 학습합니다. 마스킹 ID 단독 일치, 음수 지연, 결과 불명은 학습하지 않습니다. 서버 시계 검증 자료가 없는 현재 UI 입력에서는 자동 학습이 보류됩니다. 제출 수락과 순위·낙찰은 별도입니다.

## 로컬 데이터와 보안

설정과 로그는 개발 실행 시 프로젝트 디렉터리, 배포 실행 시 EXE가 있는 디렉터리에 저장됩니다. 비밀번호는 Windows Credential Manager, 쿠키는 Windows DPAPI로 보관합니다. 설정에는 ID만 저장하며 로그의 ID는 마스킹합니다. 기존 평문 계정과 pickle 쿠키는 보안 저장 성공 후 제거됩니다.

노출된 적이 있는 비밀번호는 릴리스 전에 반드시 변경하고 기존 옥션 세션을 모두 로그아웃하십시오.

## 취소와 복구

각 작업은 자신이 만든 Chrome만 닫으며 사용자의 일반 Chrome은 종료하지 않습니다. 취소는 작업별 이벤트를 전달하며 브라우저가 취소를 승인하기 전에 발화한 제출은 되돌릴 수 없습니다. 제출 결과 불명은 옥션 내역에서 확인해야 하며 자동으로 재시도하지 않습니다. 앱 전용 브라우저가 손상되었거나 버전이 다르면 전체 배포 패키지를 다시 설치하십시오.

## 빌드 및 검증

```powershell
py -3 -m pip install -r requirements.txt
py -3 -m pytest -q
pyinstaller --clean main.spec
```

로컬 브라우저 통합시험 및 4가지 환경의 모의 제출 측정:

```powershell
$env:AUCTON_LOCAL_BROWSER_TESTS='1'
.\venv\Scripts\python.exe -m pytest tests/test_browser_bidding.py -q
.\venv\Scripts\python.exe scripts/benchmark_browser.py --runs 1000 --output benchmark_browser.json
```

측정은 고정 버전 headless Chrome과 로컬 모의 서버만 사용합니다. 실서비스·일반 입찰·데스크톱 화면 모드의 정확도 보장으로 해석하지 않습니다. 상세 구현·측정 상태는 `개선.md`를 참조하세요.

## 다중 EXE 실행 수정본

다중 실행 1차 수정본은 `dist/multi-instance-fix/main/main.exe`에 빌드했으며, 현재는 위의 로그인 방식/진행 로그 수정본을 사용합니다. 같은 폴더의 `_internal`을 함께 유지한 채 실행합니다. 기존 파일과 실행 중인 프로그램은 교체하거나 종료하지 않았습니다. 최신 폴더에는 프로젝트에 남아 있는 계정 ID 목록과 UI 설정을 초기값으로 복사했으며, 사용 중인 창의 최신 설정과 일치하는지 시작 전에 확인합니다.

브라우저마다 패치용 드라이버 경로를 분리하고, 브라우저 시작을 병렬 처리합니다. 설정 저장은 고유 임시파일과 제한된 재시도로 충돌을 줄입니다. 같은 폴더에서 실행한 창들은 저장 파일을 공유하므로 다음 시작 시에는 마지막 저장값이 사용되지만, 이미 시작한 입찰의 명세와 실행 상태는 창별로 독립적입니다.

프로그램 3개가 각각 고정 입찰 3개를 준비하는 전체 흐름을 로컬에서 검증했습니다. 준비 여유 80초와 운영 지각 허용값 5ms 조건에서 9건 모두 수신됐습니다. 40초 준비 시험의 실패와 짧은 장전 여유에서의 만료 기록도 `개선.md`에 남겼습니다. 준비 완료를 확인하지 않고 마지막 입찰 실행을 보장하지 않습니다.

```powershell
.\venv\Scripts\python.exe scripts/check_multi_instance.py --full
```

실제 옥션 검증은 제출 직전까지 dry-run이 기본입니다. 실제 입찰은 사용자가 명시적으로 활성화한 검증 계정과 상품에서만 수행하십시오.
